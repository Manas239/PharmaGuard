1. Project Overview

PharmaGuard is a clinical pharmacogenomics web application designed to help users upload a genomic VCF file and evaluate the risk of selected drugs based on genetic variations. The project is built as a hackathon-style demo that combines a modern web frontend with a backend service layer that prepares and validates the input, calls an ML / Python analysis backend when available, and gracefully falls back to mock clinical data.

The core idea is simple but powerful: if a patient has gene variants that affect drug metabolism, the system can identify whether a drug may be ineffective, requires dose adjustment, or may be toxic. This is highly relevant in personalized medicine, especially for drugs influenced by genes such as CYP2C19, CYP2C9, CYP2D6, TPMT, DPYD, and SLCO1B1.

2. Problem Statement and Business Value

In real clinical practice, patients respond differently to the same drug due to pharmacogenomic variation. Standard treatment often ignores this factor and can lead to ineffective therapy or harmful side effects. PharmaGuard addresses this by making pharmacogenomic decision support easier to understand and more usable for clinicians, researchers, and developers.

The software brings together VCF input, drug selection, risk analysis, clinical guidance, and conversational explanation in one user-friendly workflow.

Business Impact

  • Improves patient safety through better drug matching
  • Helps clinicians personalize treatment plans
  • Reduces drug-related adverse events
  • Supports educational and prototype use in genomics labs

Target Use Case

  • VCF genomic file upload
  • Drug list selection for analysis
  • Clinical report generation
  • AI-based explanation via chat

Backend

Core Architecture

The application follows a three-layer structure: frontend UI, Node-based API server, and optional Python-based analysis backend. The backend receives multipart form submissions containing a VCF file and selected drugs. It validates the file, optionally forwards the request to Python ML services, and finally returns risk analysis results or a mock response for demo purposes.

4. System Workflow

The end-to-end workflow is clear and user-friendly. The user uploads a VCF file, enters or selects drugs, and triggers analysis. The backend validates extension and file size, generates a patient payload, and either forwards it to a Python engine or uses a predefined mock response. The frontend displays structured results, including risk label, confidence score, severity, dosage guidance, and gene-level clinical context.

  1. User uploads a .vcf file in the frontend.
  2. Frontend sends a multipart request to /api/analyze.
  3. Backend validates the file and required drugs.
  4. Optional Python validator runs to confirm the VCF format.
  5. Analysis is forwarded to a Python backend if configured.
  6. Mock or real results are normalized and displayed.
  7. AI chat answers follow-up questions using the generated report context.

6. Data Flow and Logic

The backend organizes the flow around two significant concerns: file validation and result shaping. In the analysis route, it reads the uploaded VCF file, ensures the file extension is valid, checks file size, and extracts user-selected drugs from the request. It then prepares a payload to send to the Python service or falls back to canned JSON that mimics a drug safety report.

Each result object contains information such as patient ID, drug name, timestamp, risk label, confidence score, gene profile, phenotype, and clinical recommendation. This structured data is later consumed by the frontend ResultsPanel and the AI chat system.

9. Interview Questions with Answers

Q1: What problem does PharmaGuard solve?

A: PharmaGuard solves the challenge of matching a patient’s genomic profile to drug safety and dosage recommendations. It helps detect cases where a drug may be ineffective, toxic, or require dose reduction based on genetic variation.

Q2: Why is VCF validation important in this project?

A: VCF validation is essential because genomic data is sensitive and must follow a valid structure. If the file is malformed, corrupted, too large, or wrong type, the system rejects the request before analysis. This ensures reliability and prevents inaccurate clinical interpretation.

Q3: What is the role of the backend in this architecture?

A: The backend acts as the orchestration layer. It validates requests, stores logs, forwards data to external Python services, handles error recovery, and ensures that the frontend receives a consistent response structure.

Q4: Why is this project relevant in personalized medicine?

A: Because different patients can metabolize the same drug very differently depending on genetic variants. The project reflects how pharmacogenomics can create safer, more personalized clinical decisions, especially with commonly tested genes like CYP2C19 and TPMT.

Q5: What is the purpose of the Groq chat integration?

A: The chat feature is used to answer natural-language questions about the generated reports. It grounds the response in the analysis results so the user can ask follow-up questions like dose adjustment, gene impact, or toxicity explanation.

Q6: What are the biggest opportunities for future improvement?

A: The most important next step is to connect the system to a real pharmacogenomics engine that parses actual VCF variant annotations. Another improvement is to build stronger clinical validation rules, integrate database-backed patient histories, and add secure authentication for healthcare use.

10. Conclusion

PharmaGuard is a well-structured and highly relevant project that combines modern web development with clinical decision support. It is more than just a dashboard; it is a prototype for how genomic data can be transformed into understandable drug safety guidance. The system is especially impressive because it blends backend validation, external service integration, user interaction, and AI-assisted explanation into a single workflow.

Even though it is clearly positioned as a hackathon/demo project, the architecture is practical and extensible. With a real Python pharmacogenomics engine and additional clinical validation, the project could evolve into a serious healthcare technology solution.
